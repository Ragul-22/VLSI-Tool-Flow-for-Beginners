📖 What is VLSI Design?

VLSI (Very Large Scale Integration) is the process of creating integrated circuits by combining millions or billions of transistors on a single chip. When you design a CPU, GPU, or any custom chip, you go through a series of steps — this series is called the design flow.

The open-source tools covered in this guide implement a complete flow from a hardware description (RTL — Register-Transfer Level code) all the way to a GDSII file — the final file format sent to a chip foundry for fabrication.

🧩 What is RTL?

RTL (Register-Transfer Level) is your design written in a hardware description language like Verilog or VHDL. Think of it as code that describes what your circuit does — like a Python script, but for hardware.

📦 What is a Netlist?

A netlist is the output of synthesis — it describes your circuit as interconnected logic gates (AND, OR, NAND, etc.) instead of abstract Verilog. It's the "compiled" version of your RTL.

🗺 What is a DEF/LEF file?

DEF (Design Exchange Format) stores the physical placement of cells and wires on the chip. LEF (Library Exchange Format) stores the geometry rules of the cell library you're using.

📤 What is GDSII?

GDSII (Graphic Database System II) is the final output — a binary file containing all the exact polygon shapes at every layer of the chip. Foundries use this to physically manufacture your chip.

💡
All three tools in this guide are completely free and open-source. The full flow (RTL → GDSII) can be run on a laptop without any commercial license.

⚡ Yosys — Synthesis

Y
Yosys Open Synthesis Suite
RTL Synthesis Framework — converts Verilog to gate-level netlists

Yosys is the open-source synthesis engine that reads your Verilog or SystemVerilog, parses it, optimises it, and then maps it to real logic cells from a technology library (called a PDK — Process Design Kit). Think of it as a compiler, but for hardware.

🌐
Official site: yosyshq.net/yosys | GitHub: YosysHQ/yosys

How Yosys Works — Step by Step

  1. Parse — Yosys reads your Verilog file and builds an internal AST (Abstract Syntax Tree) representing the design.
  2. Elaborate — It resolves module instances, parameters, and generates/always blocks into a flat internal representation.
  3. Optimise — Optimisation passes reduce the logic: constant propagation, dead code elimination, Boolean simplification.
  4. Map to gates — The abc engine maps your logic to real cells from the .lib liberty file (e.g. sky130 standard cells).
  5. Write netlist — Outputs a gate-level Verilog netlist (.v) ready for place & route.

Your First Yosys Synthesis

Here's a simple 4-bit counter in Verilog and how to synthesise it:

verilog — counter.v
// Simple 4-bit synchronous counter
module counter (
    input  clk,       // clock
    input  rst_n,     // active-low reset
    output reg [3:0] count  // 4-bit output
);

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        count <= 4'b0000;   // reset to 0
    else
        count <= count + 1;  // increment
end

endmodule
tcl — synth.tcl (Yosys script)
# Step 1: Read the Verilog source
read_verilog rtl/counter.v

# Step 2: Run synthesis for sky130 (SkyWater 130nm PDK)
synth_sky130 -top counter -flatten

# Step 3: Map flip-flops and combinational logic
dfflibmap -liberty pdk/sky130_fd_sc_hd__tt_025C_1v80.lib
abc -liberty pdk/sky130_fd_sc_hd__tt_025C_1v80.lib

# Step 4: Clean up and write output netlist
clean
write_verilog synth/counter_synth.v

# Optional: Show statistics
stat
bash — run it
yosys -c synth.tcl
⚠️
Make sure you have the sky130 PDK liberty file (.lib) downloaded before running synthesis. You can get it from the SkyWater PDK GitHub repo or via volare / open_pdks.

🛣 OpenROAD — Place & Route

OR
OpenROAD
Automated Physical Design — from netlist to routed layout

OpenROAD is a full physical design tool: it takes the synthesised netlist from Yosys and transforms it into a real chip layout. It handles floorplanning, cell placement, clock tree synthesis, routing, and sign-off timing checks — all in one integrated flow.

🌐
Official site: theopenroadproject.org | GitHub: The-OpenROAD-Project/OpenROAD

Installing OpenROAD

bash — easiest: use OpenROAD-flow-scripts
# Clone the OpenROAD flow scripts (includes everything)
git clone --recursive https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts

# Run the install script (Linux recommended)
cd OpenROAD-flow-scripts
sudo ./setup.sh

# Build OpenROAD
./build_openroad.sh

# Verify
./tools/install/OpenROAD/bin/openroad -version
🐳
Tip for beginners: The easiest way to get started is using the Docker image which has everything pre-installed: docker pull openroad/flow-scripts

Physical Design Stages Inside OpenROAD

  1. Floorplanning — Define the die area (how big the chip is), set up IO pin locations, and place any large macros (memories, PLLs).
  2. Power Planning — Create a power delivery network (PDN): vertical/horizontal metal stripes supplying VDD and GND to every cell.
  3. Placement (GPL) — Global placement: cells are placed to minimise wire length using force-directed algorithms. Then detailed placement legalises them to exact grid positions.
  4. Clock Tree Synthesis (CTS) — Build a balanced clock distribution network so every flip-flop sees the clock at the same time (minimise skew).
  5. Routing — Global routing plans the paths. Detailed routing draws the actual metal wires layer by layer using DRC rules.
  6. Sign-off — Run static timing analysis (STA) with OpenSTA, check IR-drop, antenna violations, and extract parasitics.

A Complete OpenROAD TCL Flow Script

tcl — pnr_flow.tcl
# ── Read technology libraries ──────────────────────────────
read_lef pdk/sky130_fd_sc_hd.tlef   ;# technology LEF (layers)
read_lef pdk/sky130_fd_sc_hd.lef    ;# cell LEF (cell shapes)
read_liberty pdk/sky130_fd_sc_hd__tt_025C_1v80.lib

# ── Read the synthesised netlist ──────────────────────────
read_verilog synth/counter_synth.v
link_design counter

# ── Apply timing constraints ──────────────────────────────
read_sdc constraints/counter.sdc

# ── 1. Floorplan ─────────────────────────────────────────
initialize_floorplan \
    -die_area  "0 0 100 100" \
    -core_area "10 10 90 90" \
    -site      unithd

# Place IO pins around the perimeter
place_pins -hor_layers met2 -ver_layers met3

# ── 2. Power Planning ────────────────────────────────────
add_global_connection -net VDD -pin_pattern "VPB|VPWR" -power
add_global_connection -net VSS -pin_pattern "VNB|VGND" -ground
global_connect

pdngen   ;# generate power delivery network

# ── 3. Placement ─────────────────────────────────────────
global_placement -density 0.65
detailed_placement

# ── 4. Clock Tree Synthesis ──────────────────────────────
clock_tree_synthesis -buf_list "sky130_fd_sc_hd__clkbuf_4 sky130_fd_sc_hd__clkbuf_8"
detailed_placement   ;# re-legalise after CTS

# ── 5. Routing ───────────────────────────────────────────
global_route -guide_file pnr/route.guide
detailed_route -output_drc pnr/route_drc.rpt

# ── 6. Sign-off timing check ─────────────────────────────
report_checks -path_delay min_max -fields {slew cap input nets fanout}
report_wns   ;# worst negative slack
report_tns   ;# total negative slack

# ── Write outputs ─────────────────────────────────────────
write_def     pnr/counter_routed.def
write_verilog pnr/counter_final.v
tcl — counter.sdc (constraints)
# Set clock: 10ns period = 100 MHz
create_clock [get_ports clk] -name clk -period 10

# Set input/output delays
set_input_delay  2 -clock clk [get_ports rst_n]
set_output_delay 2 -clock clk [get_ports count]
bash — run it
openroad -exit pnr_flow.tcl | tee pnr/run.log

🔬 KLayout — Viewing & Verification

KL
KLayout
Layout Viewer, DRC Engine & GDSII Export

KLayout is a powerful layout viewer and editor. In an open-source VLSI flow it serves three important roles: (1) viewing your DEF/GDSII layout, (2) running DRC (Design Rule Check) to catch violations before tapeout, and (3) running LVS (Layout vs. Schematic) to verify the layout matches your netlist.

🌐
Official site: klayout.de | GitHub: KLayout/klayout

Installing KLayout

bash — Linux
# Ubuntu/Debian via apt
sudo apt-get install -y klayout

# Or download the binary package from klayout.de
# .deb packages available for Ubuntu/Debian
wget https://www.klayout.org/downloads/Ubuntu-22/klayout_0.29.4-1_amd64.deb
sudo dpkg -i klayout_0.29.4-1_amd64.deb

Three Ways to Use KLayout

👁 GUI Viewer

Open klayout my_chip.gds or klayout my_chip.def and visually inspect every metal layer, cell instance, and wire. Great for debugging routing issues.

📏 DRC (Design Rule Check)

Run a .drc rule file against your layout to detect spacing violations, width errors, and enclosure errors. Mandatory before tapeout.

🔁 LVS (Layout vs. Schematic)

Compare your routed layout against the original netlist to verify nothing changed. Detects open circuits, short circuits, and wrong connections.

🐍 Scripting (Ruby/Python)

KLayout has a full scripting API. Automate DRC/LVS, manipulate cells, generate patterns, or convert file formats with Ruby or Python scripts.

Converting DEF + LEF → GDSII with KLayout

After OpenROAD produces the routed .def, KLayout merges it with the cell GDSII views to produce the final .gds tapeout file:

python — def_to_gds.py
import pya   # KLayout Python binding

# Create a layout object
layout = pya.Layout()

# Load the technology LEF (layer definitions)
reader_options = pya.LoadLayoutOptions()
reader_options.lefdef_config.map_file = "pdk/sky130.map"

# Read all cell LEF files
layout.read("pdk/sky130_fd_sc_hd.lef")

# Read the cell GDSII views
layout.read("pdk/sky130_fd_sc_hd.gds")

# Read the routed DEF (places cells, routes wires)
layout.read("pnr/counter_routed.def", reader_options)

# Write the final GDSII
layout.write("gds/counter.gds")
print("GDSII written successfully!")
bash — run it
klayout -b -r def_to_gds.py

Running DRC with sky130 rules

KLayout uses .lydrc or .drc scripts to check your layout. The sky130 PDK includes ready-made DRC scripts:

bash — run sky130 DRC
# The sky130 DRC rule deck comes with open_pdks
klayout -b \
  -r $PDK_ROOT/sky130A/libs.tech/klayout/drc/sky130A.drc \
  -rd input=gds/counter.gds \
  -rd topcell=counter \
  -rd report=drc/drc_results.xml \
  gds/counter.gds
ℹ️
DRC output is an XML file you can open back in KLayout's GUI. Each violation is shown as a highlighted region on the layout with an error message — very beginner-friendly!

🚀 Full Example: Counter Chip End-to-End

Let's put it all together and run the complete flow for our 4-bit counter. Here's a single Makefile that orchestrates everything:

makefile
# ── Configuration ─────────────────────────────────────────
DESIGN   = counter
TOP      = counter
PDK_ROOT = /home/user/pdks/sky130A
LIB      = $(PDK_ROOT)/libs.ref/sky130_fd_sc_hd/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
LEF      = $(PDK_ROOT)/libs.ref/sky130_fd_sc_hd/techlef/sky130_fd_sc_hd.tlef \
            $(PDK_ROOT)/libs.ref/sky130_fd_sc_hd/lef/sky130_fd_sc_hd.lef

# ── All targets ───────────────────────────────────────────
.PHONY: all synth pnr gds drc clean

all: gds

# Step 1 – Synthesis with Yosys
synth: rtl/$(DESIGN).v synth/synth.tcl
	mkdir -p synth
	yosys -c synth/synth.tcl | tee synth/synth.log

# Step 2 – Place and Route with OpenROAD
pnr: synth pnr/pnr_flow.tcl
	mkdir -p pnr
	openroad -exit pnr/pnr_flow.tcl | tee pnr/pnr.log

# Step 3 – Convert DEF to GDSII with KLayout
gds: pnr
	mkdir -p gds
	klayout -b -r scripts/def_to_gds.py

# Step 4 – Run DRC
drc: gds
	mkdir -p drc
	klayout -b \
	  -r $(PDK_ROOT)/libs.tech/klayout/drc/sky130A.drc \
	  -rd input=gds/$(DESIGN).gds \
	  -rd topcell=$(TOP) \
	  -rd report=drc/drc_results.xml \
	  gds/$(DESIGN).gds

clean:
	rm -rf synth/ pnr/ gds/ drc/
bash — run the full flow
# Run everything from RTL → GDSII
make all

# Or run individual stages
make synth   # synthesis only
make pnr     # place and route
make gds     # gdsii export
make drc     # design rule check

# Open the result in KLayout GUI
klayout gds/counter.gds
🎉
After a successful make all, open gds/counter.gds in KLayout and you'll see your chip — all the placed standard cells, metal routing, power rails, and IO pins rendered as coloured polygons!

📚 Glossary of Key Terms

RTLRegister-Transfer Level. A hardware description at the abstraction level of registers and logic operations, written in Verilog or VHDL.
SynthesisThe process of converting RTL code into a gate-level netlist using cells from a standard cell library.
NetlistA description of a circuit as a list of gate instances and the nets (wires) connecting them.
PDKProcess Design Kit. Files provided by the foundry describing the manufacturing process: cell libraries, design rules, SPICE models, layer definitions.
LEFLibrary Exchange Format. Describes cell and technology geometry: layer names, routing rules, cell pin locations, and obstruction areas.
DEFDesign Exchange Format. Stores the physical placement of cells and routing of wires for a specific design instance.
Liberty (.lib)A timing/power model file for standard cells. Describes propagation delays, setup/hold times, leakage power at various operating conditions.
FloorplanningThe first physical design step: defining die and core area size, placing IO pins, and positioning hard macros.
PlacementThe step that assigns an (x, y) location to each standard cell within the core area.
CTSClock Tree Synthesis. Building a balanced tree of clock buffers to distribute the clock signal to all flip-flops with minimal skew.
RoutingDrawing metal wire connections between cell pins on the available metal layers, following design rule constraints.
STAStatic Timing Analysis. Verifying that all data paths meet setup and hold timing constraints without running simulation.
SDCSynopsys Design Constraints. A TCL-based file format specifying clocks, input/output delays, and false paths for timing analysis.
DRCDesign Rule Check. Verifying that the layout geometry obeys the foundry's manufacturing constraints (minimum width, spacing, overlap rules, etc.).
LVSLayout vs. Schematic. Comparing the extracted netlist from the physical layout against the intended netlist to confirm they match.
GDSIIGraphic Database System II. The industry-standard binary file format for IC layout polygons — the final file submitted to a foundry for chip fabrication.
PDNPower Delivery Network. The system of metal stripes and vias distributing VDD and GND throughout the chip.
WNS / TNSWorst Negative Slack / Total Negative Slack. Timing metrics — negative values indicate timing violations that must be fixed before tapeout.
sky130SkyWater 130nm open-source PDK, released by Google and SkyWater Technology. The most popular PDK for learning and open-source chip design.
abcA logic synthesis and verification tool integrated into Yosys. Performs technology mapping — converting logic into cells from a .lib liberty file.
